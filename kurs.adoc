==  Требования к разработке

* Для разработки должна использоваться отладочная плата: XNUCLEO-F411RE
* Устройство должно измерять ЧСС и температуру каждые 10 минут.
* Расчёт уровня глюкозы с помощью ЧСС и температуры.
* Вывод значений в UART.
* Температурный датчик (JP402) и ЧСС (датчик *поиск*).


==  USART

USART (Universal Synchronous/Asynchronous Receiver/Transmitter) — универсальный приёмопередатчик, поддерживающий как асинхронный (UART), так и синхронный режим передачи данных. Используется для последовательного обмена данными между микроконтроллером и внешними устройствами: ПК, модулями связи, датчиками и др.

В асинхронном режиме данные передаются с помощью старт-бита, 8/9-битной информации, необязательного бита чётности и одного или двух стоп-битов. В синхронном режиме дополнительно используется тактовая линия (CK) для синхронизации.

Функциональные возможности USART в STM32:
- поддержка полнодуплексной передачи;
- настройка скорости, длины слова, чётности, стоп-битов;
- работа с прерываниями и DMA;
- управление потоком (RTS/CTS);
- режимы LIN, SmartCard, IrDA и мультипроцессорная связь.

=== Пояснения к регистрам USART STM32F411

==== USART_SR (Status Register)
Регистр состояния. Отражает текущее состояние передатчика и приёмника. Основные биты:
- RXNE — приём завершён, данные готовы к чтению;
- TXE — передатчик готов принять новый байт;
- TC — завершена передача всего кадра;
- ORE, NE, FE — ошибки (переполнение, шум, ошибка кадра);
- PE — ошибка чётности.

==== USART_DR (Data Register)
Регистр данных. При чтении — содержит принятый байт, при записи — байт, подлежащий отправке.

==== USART_BRR (Baud Rate Register)
Регистр делителя частоты, используемый для задания скорости передачи данных (baud rate). Формат зависит от режима oversampling (по 8 или 16).

===== USART_CR1 (Control Register 1)
Основной регистр управления. Включает USART (бит UE), задаёт формат кадра (длина слова, чётность), включает прерывания, активирует приёмник и передатчик.

==== USART_CR2 (Control Register 2)
Расширенное управление. Настройка количества стоп-битов, включение синхронного режима (тактовая линия), LIN-мод, адрес для мультипроцессорной связи и др.

==== USART_CR3 (Control Register 3)
Дополнительное управление: включение DMA, управление аппаратным контролем потока (RTS/CTS), настройки SmartCard, IrDA и обработка ошибок.

==== USART_GTPR (Guard time and prescaler register)
Используется в специальных режимах (SmartCard). Настраивает задержку защиты (guard time) между байтами и предделитель тактовой частоты.

== Основные датчики для измерения температуры и ЧСС

=== Описание температурного датчика JP402

Температурный зонд JP402 представляет собой *неинвазивный медицинский датчик температуры*, предназначенный для измерения *температуры поверхности тела человека*. Он используется в клинических и исследовательских условиях, включая мониторы жизненных показателей, аппараты анестезии и неонатальные системы слежения.

==== Основные характеристики

* Тип чувствительного элемента: NTC-термистор (Negative Temperature Coefficient)
* Диапазон температур: от +25 °C до +45 °C
* Точность измерения: ±0.1 °C…±0.2 °C
* Время отклика: 1–2 секунды
* Совместимость: мониторы Mindray, Philips, GE, Nihon Kohden и др.
* Выходной сигнал: аналоговый (напряжение, зависящее от сопротивления)
* Корпус: медицинский термопластик, пригоден для дезинфекции
* Способ крепления: с помощью медицинского пластыря или фиксатора

==== Принцип работы

NTC-термистор, встроенный в датчик, изменяет сопротивление в зависимости от температуры: при *повышении температуры сопротивление уменьшается*. 

Подключив термистор в виде делителя напряжения, мы можем измерить выходное напряжение с помощью АЦП STM32 и преобразовать его в температуру.

Для этого:
1. Используется формула Бета или таблица калибровки;
2. Устанавливается длительное время выборки АЦП (например, 480 тактов);
3. Из напряжения вычисляется сопротивление, а затем температура.

===== Схема подключения

- Один вывод термистора подключается к VDDA (3.3 В)
- Второй вывод — через резистор (10 кОм) к земле (GND)
- Сигнал (средняя точка делителя) подаётся на аналоговый вход микроконтроллера, например, PA0 (ADC1_IN0)

===== Преимущества использования

* Высокая чувствительность к температуре
* Подходит для непрерывного мониторинга состояния пациента
* Быстрое реагирование и стабильность
* Совместимость с медицинскими стандартами и приборами

=== Принцип работы пульсометра

==== Физическая основа измерения
Измеряется частота периодических колебаний, вызываемых сокращениями сердца.  
Пульс может сниматься оптическим датчиком (фотоплетизмография), пьезодатчиком давления или при помощи электродов. Во всех случаях на выходе формируется **электрический импульс** каждый раз, когда происходит сердечный выброс.

==== Формирование электрического сигнала
* **Датчик** располагается на коже (палец, запястье, ушная мочка).  
* При каждом сердечном ударе изменяется либо поток света (оптика), либо давление (механика), либо потенциал кожи (ЭКГ).  
* Эти изменения преобразуются в узкие электрические импульсы одинаковой полярности и уровня.

==== Преобразование в цифровую форму
Импульсы поступают на вход таймера-счётчика микроконтроллера:
* На таймере активируется режим **захвата** (input-capture).  
* Каждый фронт импульса фиксирует текущее значение счётного регистра.  
* Из разницы двух соседних захватов получают длительность интервала R-R (между ударами) в тактах системной частоты.

==== Расчёт частоты сердечных сокращений
Частота (BPM) вычисляется по формуле:

[latexmath]
++++
\text{BPM} = \frac{60\,000\ \text{мс}}{\Delta t_{\text{удар}}}
++++

где `Δt` — время между двумя подряд фронтами.  
Для микроконтроллера время обычно сначала переводится из тактов в микросекунды, затем — в удары в минуту.

=== Фильтрация и подавление помех
* **Прерывание таймера** отбрасывает ложные срабатывания короче заданного окна (debounce).  
* Скользящее среднее или медианный фильтр из 3-5 последних интервалов сглаживает естественный джиттер.  
* При длительном отсутствии импульсов счётчик сбрасывается, чтобы не выдавать ноль или бесконечность.

=== Вывод и использование данных
Готовое значение ЧСС:
* передаётся в алгоритмы (например, для коррекции расчёта глюкозы);  
* отображается на дисплее или отправляется в отладочный порт.

Такой поток «датчик → захват таймера → расчёт Δt → BPM → фильтр» обеспечивает надёжное и энергоэффективное измерение пульса без привязки к конкретной реализации программных классов.








== Описание медицинского кожного термодатчика

Этот датчик предназначен для неинвазивного измерения температуры на поверхности тела пациента (кожи). Он представляет собой небольшую капсулу (или цилиндр), внутри которой размещён чувствительный элемент — обычно термистор (NTC) или платиновый терморезистор (Pt100/Pt1000). 

Основные особенности:
- Способ крепления: датчик приклеивается к коже с помощью медицинского пластыря или специального фиксатора.

- Чувствительный элемент: 

  - В случае NTC-термистора, сопротивление _уменьшается_ при повышении температуры.

  - В случае платинового терморезистора (Pt100/Pt1000), сопротивление _возрастает_ с ростом температуры.

- Диапазон измерений: обычно от +25 °C до +45 °C (для измерения температуры тела).

- Точность: ±0,1…0,2 °C (зависит от типа элемента, конструкции датчика и требований стандарта).

- Совместимость: такие зонды часто подключаются к многофункциональным медицинским мониторам или специализированным термометрам. 

В процессе работы:

1. **Контакт с кожей**: датчик фиксируется на требуемом участке тела (например, в области подмышечной впадины, на груди и т.д.).

2. **Изменение сопротивления**: когда температура кожи меняется, сопротивление чувствительного элемента тоже меняется.

3. **Преобразование сигнала**: подключённый прибор (монитор) пропускает небольшой ток через датчик, фиксирует напряжение или ток и вычисляет текущее сопротивление.

4. **Расчёт температуры**: используя калибровочные данные (Beta-формулу для NTC или уравнение для Pt100), регистратор преобразует сопротивление в значение температуры.

5. **Отображение результата**: данные выводятся на дисплей медицинского прибора или сохраняются для мониторинга.

Таким образом, медицинский кожный термодатчик позволяет получать быстрые и точные показания температуры поверхности тела пациента в реальном времени, что особенно важно в операционных залах, палатах интенсивной терапии и при долгосрочных исследованиях.



При расчёте сопротивления NTC-термистора при температуре 37°C, если:
- R₀ = 10 000 Ω при T₀ = 25 °C (298,15 K),
- β = 3950,
- T = 37 °C (310,15 K),

используется следующая упрощённая Beta-формула:

[latexmath]
++++
R = R_0 \cdot \exp \Bigl[\beta \Bigl(\frac{1}{T} - \frac{1}{T_0}\Bigr)\Bigr]
++++

где:

- _R_ — сопротивление термистора при неизвестной температуре _T_,
- _R₀_ — сопротивление при эталонной температуре _T₀_,
- _β_ — константа термистора (Beta-параметр),
- _T_ — текущая температура (в кельвинах), при которой определяется сопротивление _R_,
- _T₀_ — эталонная температура (в кельвинах).

Подставим значения и вычислим по шагам:

[latexmath]
++++
\frac{1}{T} = \frac{1}{310.15} \approx 0.003225, \\
\frac{1}{T_0} = \frac{1}{298.15} \approx 0.003356, \\[6pt]
\left(\frac{1}{T} - \frac{1}{T_0}\right) \;=\; 0.003225 \;-\; 0.003356 
\;=\; -0.000131, \\[6pt]
\beta \,\Bigl(\frac{1}{T} - \frac{1}{T_0}\Bigr) 
\;=\; 3950 \times (-0.000131) 
\;\approx\; -0.51745, \\[6pt]
\exp(-0.51745) \;\approx\; 0.596, \\[8pt]


R \;\approx\; 10\,000\,\Omega \;\times\; 0.596 \;=\; 5960\,\Omega.
++++

Следовательно, при 37 °C сопротивление термистора (изначально 10 кΩ при 25 °C) уменьшается примерно до 5,96 кΩ.


== Формулы связи для температуры, ЧСС и глюкозы

Формула  используется для расчёта уровня глюкозы (гликемии) на основе температуры:

[latexmath]
++++
GL(t) = K \cdot [T(t - \tau) - T(0)]
++++

где:

* *GL(t)* — уровень глюкозы в крови в момент времени *t*, измеряемый в ммоль/л
* *K* — коэффициент пропорциональности (ммоль/л·°C)
* *T(t − τ)* — температура тела (в °C) в момент времени с учётом задержки *τ*
* *T(0)* — базовая температура тела (в °C), соответствующая нулевому уровню гликемии
* *τ* — временная задержка между изменением температуры и уровнем глюкозы (в минутах)


[latexmath]
++++
\mathrm{HOMA\!-\!IR}(t)=
\frac{I_{\text{HR}}(t)\,[\text{мЕд/л}]\;\times\;GL(t)\,[\text{ммоль/л}]}{22.5}
++++

Здесь  

* *\(I_{\text{HR}}(t)\)* — «виртуальная» концентрация инсулина, полученная из сердечного ритма.  
  Амплитуда и форма RR‑интервалов сначала нормируются, затем через эмпирическую регрессию сопоставляются с плазменным уровнем инсулина.  
  Такой приём позволяет обойтись без инвазивного анализа крови при каждом цикле измерений.  
* *\(GL(t)\)* — концентрация глюкозы, уже рассчитанная из температурного профиля кожи (см. раздел 3.2.2).  
* 22,5 — безразмерная константа, введённая Мэттьюсом и соавт. для перевода произведения «инсулин × глюкоза» в стандартную шкалу устойчивости к инсулину.

Таким образом, последовательность «ЧСС → \(I_{\text{HR}}\) → HOMA‑IR» дополняет ранее полученную температуру‑зависимую оценку глюкозы и даёт комплексный цифровой маркер метаболического состояния без забора крови.


== Алгоритм обработки данных

При обработке равноточных измерений для каждой группы вычисляется среднее значение по формуле:

[latexmath]
++++
\overline{X}_1 = \frac{1}{n} \sum_{i=1}^{n} \overline{X}_{i}, \quad 
\overline{X}_2 = \frac{1}{n} \sum_{j=1}^{n} X_{j}
++++

где \( X_i \) — результаты измерений.

Итоговое среднее значение по всем группам определяется как среднеарифметическое значений групп:

[latexmath]
++++
\overline{X} = \frac{1}{2}(P_1 \overline{X}_1 + P_2 \overline{X}_2)
++++

где L — число групп.

Среднеквадратическое отклонение определяется по формуле:

[latexmath]
++++
S = \sqrt{ \frac{1}{n-1} \sum_{i=1}^{n} (X_i - \overline{X})^2 }
++++

что позволяет количественно оценить разброс измерений относительно среднего значения.

Веса групп назначаются в соответствии с формулой:

[latexmath]
++++
P_j = \frac{q_j}{\sum_{k=1}^{L} q_k}
++++

где:

- \( S^2(A_j) \) — дисперсия результатов измерений j-й группы  
- \( S^2(\theta_j) \) — СКО НСП  
- \( S^2(\theta_j) = S^2(A_j) + S^2(\theta_j) \)  
- \( q_j = \frac{1}{S^2(A_j)} \)

Суммарное среднеквадратическое отклонение результата измерения определяется через сумму весов с учётом вклада каждой группы.

[latexmath]
++++
S = \sqrt{ \frac{1}{\sum_{j=1}^{L} P_j} }
++++


Доверительная граница погрешности рассчитывается с использованием коэффициента Стьюдента:

[latexmath]
++++
\Delta X = t(q, f) \cdot S
++++


где \( t(q, f) \) — коэффициент Стьюдента для доверительного уровня,  
\( f \) — число степеней свободы.

На верхнем уровне моделирования вся система представлена одной функцией «Неинвазивный глюкометр», которая объединяет в себе сбор и обработку входных сигналов, управление по нормативам и калькуляцию результата. В качестве входов эта функция получает от пользователя физиологические параметры (температуру тела, частоту сердечных сокращений и персональные характеристики), а также от датчиков – сырые показания температуры и пульса. Управление осуществляется двумя потоками требований: техническими стандартами и нормативными актами, а также медицинскими протоколами калибровки. Микроконтроллер вместе с датчиками температуры и ЧСС выступают в роли механизмов, выполняющих фильтрацию, масштабирование и вычисления. На выходе вся эта цепочка генерирует данные о текущем состоянии уровня глюкозы в крови, которые передаются обратно пользователю в виде понятного отчёта.

*A1 «Обработка сигнала температуры»*

Микроконтроллер принимает аналоговый сигнал с термодатчика, преобразует его в цифровую форму и применяет алгоритмы фильтрации и корректировки, используя индивидуальные коэффициенты калибровки. В результате формируется точное значение температуры, адаптированное под физические характеристики конкретного пользователя и готовое к передаче на следующий этап обработки.

*A2 «Обработка сигнала ЧСС»*
Этот блок получает сырое измерение пульсового или электрокардиографического датчика и с учётом смещений и коэффициентов, выданных управляющим процессом, удаляет артефакты и шумы, определяет интервалы между пиковыми точками сигнала и рассчитывает усреднённое значение частоты сердечных сокращений. В результате получается скорректированное значение ЧСС, отражающее актуальный ритм сердца пользователя.

*A3 «Обработка сигнала и сбор данных»*
Здесь микроконтроллер принимает уже отфильтрованные и откалиброванные цифровые значения температуры и ЧСС, выполняет дополнительное преобразование этих величин в формат, пригодный для последующих статистических расчётов, и накапливает серии измерений в буфере. Блок формирует выборки за заданные временные интервалы, обеспечивая непрерывность и полноту данных, необходимых аналитическому модулю.

*A4 «Обработка данных по измерениям»*

В этом модуле происходит статистическая интерпретация подготовленных выборок: микроконтроллер группирует накопленные данные, рассчитывает взвешенное среднее, оценку дисперсии и доверительный интервал согласно установленным методикам и нормативным требованиям, а затем формирует итоговую оценку концентрации глюкозы в крови. Параллельно он оценивает надёжность результата и формирует характеристики точности.

*A5 «Интерфейс пользователя»*

Модуль отображения отвечает за передачу рассчитанных значений глюкозы и параметров точности на экран или мобильное приложение. Интерфейс визуализирует результаты в удобном формате, уведомляет пользователя при выходе показаний за допустимые границы и предоставляет настройки частоты оповещений и единиц измерения, обеспечивая понятное взаимодействие с прибором.

*A6 «Функционально‑управленческий процесс пользовательских параметров»*

Этот процесс служит центральным «дирижёром» системы: он собирает индивидуальные данные пользователя и требования медицинских протоколов, а также нормативные стандарты, а на их основе формирует ключевые коэффициенты, смещения и пороговые величины для всех вычислительных модулей. Благодаря ему фильтрация, масштабирование сигналов и статистическая обработка выполняются с учётом специфики конкретного человека и требований регуляторов.

== Код и Классы для проекта


Ниже приведены реализации всех компонентов системы в раздельных листингах.  
Каждому классу предшествует краткое текстовое описание, поясняющее его назначение
и зону ответственности.

== Интерфейсы

=== IThread
Контракт для объектов‐потоков RTOS.  Содержит минимальный набор методов (например, `Execute()`), который вызывается планировщиком.  Позволяет запускать разные задачи единообразно и подменять их в юнит-тестах.

=== IAdcDriver
Абстракция над модулем АЦП.  Гарантирует, что реализация умеет инициализироваться и выдавать «сырое» 12-битное измерение по каналу.

=== IHrGenerator
Интерфейс драйвера генератора тестового сердечного ритма.  Позволяет устанавливать частоту прямоугольного сигнала, не раскрывая деталей таймера.

=== IHrSensor
Предоставляет метод для получения измеренной частоты (BPM) и функцию обработки прерывания.  Клиентскому коду не нужно знать, на каком входе и по какому фронту работает захват.

=== IGlucoseCalculator
Контракт высокоуровневого вычислителя, превращающего данные АЦП + ЧСС в мгновенное значение глюкозы.

=== IStatsProcess
Интерфейс для статистической агрегации значений (минимум, максимум, усреднение, σ).  Используется отчётными задачами.

=== ISerial
Единая абстракция для вывода отладочной информации.  Сохраняет возможность заменить `USART1` на другой транспорт (USB CDC, SWO, лог-буфер) без правки клиентского кода.

== Утилиты

=== Serial
Минимальный драйвер USART1 (TX = PA9).  Позволяет использовать `printf`/`iostream`, реализуя функцию `_write()`.  
Не имеет состояния — всё API статическое; реализует `ISerial`.

== Драйверы аппаратуры

=== Adc
Низкоуровневое обёртывание над `ADC1`.  Настраивает режим «single-shot», время выборки, канал PA0 (IN2) и возвращает 12-битное значение.  Реализует `IAdcDriver`.

=== HrGenerator
Конфигурирует `TIM2_CH3` (PA2) в режим PWM/toggle, создаёт тестовую квадратуру нужной частоты для стендовых испытаний.  Реализует `IHrGenerator`.

=== HrSensor
Использует захват `TIM2_CH2` (PA1) для измерения фактической частоты входного сигнала.  В ISR вычисляет период → BPM.  Реализует `IHrSensor`.

== Вычислительные модули

=== GlucoseCalculator
Преобразует:
* «сырые» показания термистора (АЦП);
* частоту сердечных сокращений;

а затем усредняет с помощью `DataProcessing`.  Реализует `IGlucoseCalculator`.

=== DataProcessing
Набор статистических/фильтрующих функций (усреднение трёх точек, сглаживание, объединение выборок).  Реализует `IStatsProcess`, чтобы задачи могли агрегировать результаты.

== Структуры данных

=== SamplePacket
[source,cpp]
----
struct SamplePacket {
    std::array<uint16_t,3> ticks;  // «сырые» АЦП значения
    std::array<uint16_t,3> bpm;    // измеренные ЧСС
};
----
Пакет из трёх последовательных измерений.  Передаётся между потоками через `MailBox`.

== RTOS-задачи

=== DataCollectionTask
Периодичность — 10 с.  
Алгоритм:
. Устанавливает частоту тестового генератора.
. Дважды опрашивает АЦП и датчик ЧСС, заполняя `SamplePacket`.
. Отправляет пакет в почтовый ящик.  
Имплементирует `IThread` и зависит от `IAdcDriver`, `IHrGenerator`, `IHrSensor`.

=== GlucoseCalcTask
Периодичность — 10 мин.  
Алгоритм:
. Берёт пакет измерений из `MailBox`.
. Использует `IGlucoseCalculator` → получает три значения глюкозы.
. Передаёт результаты модулю статистики (`IStatsProcess`) и выводит в `Serial`.  
Тоже реализует `IThread`.
